# Change: compare-runs

## Driver
"Compare = tick 2 runs." (DESIGN.md §1). The point of v2 is to answer which speech model and which AI model are best on his own recordings, as numbers and side-by-side text. v1 had `eval/score.py` for scoring; the designer asked for a word diff that "can freeze the tab" on 1 hour of speech unless it is handled.

## Depends on
v2-foundation → recording-capture (`script`, `recording.script_id`) → library-page → jobs-and-models → stt-runs (`stt_run`, `transcript_segment`, runs list) → **llm-outputs** (`analysis_run.group_id`, `input_text_sha256`, `output`, `schema_valid`, `verified`).
Not a job: comparison is cheap async code on the shared pool, so it does not use `JobService` or steps. Page served at `/analyse` (`web/analyse/index.html`); links `/analyse?rec=<id>&compare=<id>`, `/library`. Tests use the async pool and `clean_db`. Deleting a run is done by stt-runs' delete service, which calls this change's comparison cleanup.
Uses from `eval/score.py` (read-only, loaded by path, no edit): `norm`, `score`, `TECH`, `NUMBERS`, `FILLERS`, `HESITATIONS`.

## Decision
1. **Migration 0006:** `comparison(id, recording_id → recording CASCADE, created_at)`; `comparison_item(comparison_id → comparison CASCADE, side 'A'|'B', stt_run_id → stt_run CASCADE, analysis_group_id uuid null, label, primary key(comparison_id, side))`; `eval_result(id, stt_run_id → stt_run CASCADE, script_id → script SET NULL, script_sha256, metrics jsonb, created_at, unique(stt_run_id, script_sha256))`. A compared "run" is one side = an STT run plus optionally one analysis group (this matches the runs list). `analysis_group_id` has no FK (a group is a set of rows, per llm-outputs); the API checks it belongs to the same `stt_run_id`.
2. **API:** `POST /api/comparisons {recording_id, a:{stt_run_id, analysis_group_id?}, b:{...}}` → 201 `{id}`; 422 if sides are identical, runs are from different recordings, an STT run is not `done`, or the group does not belong to its STT run. `GET /api/comparisons/{id}` → header per side (label, STT model label, STT wall_ms + rtf, AI model label + wall_ms or null, date), `outputs` per kind per side with `counts`, `warnings`, `eval` (or null). `GET /api/comparisons?recording_id=` → list of `{id, created_at, a:{label}, b:{label}}` (only comparisons with 2 items). `GET /api/comparisons/{id}/transcripts` → `{a:{text}, b:{text}}` (separate so the page can render the header first). Comparisons are read-only references; nothing is copied. When an STT run is deleted (or its analysis group), the service deletes every comparison left with fewer than 2 items, in the same transaction.
3. **Counts:** pure `output_counts(kind, content)`: debrief → decisions, action_items, risks, open_questions; notes → sections, bullets; checklist → items, done; tags → tags; every kind also `unverified` (items with `verified:false`). A side whose kind has `schema_valid=false` shows "invalid output" instead of counts. Text outputs are shown side by side with no diff (DESIGN/designer D6).
4. **Different-transcripts warning:** when both sides have an analysis and their `input_text_sha256` differ, the response includes `warnings:[{code:"different_transcripts", message:"Different transcripts — AI differences may come from speech-to-text."}]` and the page shows it as a labelled line above the outputs. Same hash (even from two STT runs) → no warning. A side without an analysis → no warning, that side shows "no outputs".
5. **Word diff in the page, chunked, in a Web Worker:** `diff.js` is a pure ES module (no DOM) used by `diff-worker.js` and by node tests. Words compare by key = lowercase with surrounding punctuation removed (tonos kept: accent changes are real differences). Algorithm: anchor on words that occur exactly once in both texts (patience-style, longest increasing subsequence), split into regions between anchors, split any region larger than `maxRegionWords` (default 1500 per side) by proportion, run an LCS/Myers diff per region with a cell cap (regions over the cap become one delete+insert block). The worker posts `{progress, ops}` per batch; the main thread appends DOM in batches of ≤500 nodes per animation frame, shows "Comparing… 40%", and never blocks. Output ops `eq|del|ins`; A pane marks deleted words with strikethrough + background, B pane marks inserted words with underline + background (never colour alone). Counter: "A: x of n words differ · B: y of m".
6. **WER and tech-term recall:** `services/scoring.py` loads `eval/score.py` by importlib path and exposes `score_run(script_body_md, transcript_text)`: reference = `norm(" ".join(lines matching ^\*\*Name:\*\* text))` (same regex as `score.reference()` but on the script's stored `body_md`), then `score.score(ref, hyp)`. When `recording.script_id` is set, `POST /api/comparisons` computes (once, idempotent via the unique key) and stores `eval_result` for each side's STT run; `GET` returns it. Page shows a table: WER (all), WER ignoring hesitations, tech words right %, numbers right %, missed tech terms, lower/higher-is-better text. No script, or a script with no `**Name:**` lines → `eval:null` and the page says "no script reference for this recording". Never an exception.
7. **Page:** runs list gets a checkbox per run (STT row and each nested analysis row); at most 2 ticked (a third box is disabled with a reason line); **Compare selected (2)** enabled only at exactly 2. Compare view URL `/analyse?rec=<id>&compare=<cid>` (reload-safe). Sticky header per pane (run label, STT model + wall + RTF, AI model + wall, date), Swap, Close, tabs Transcript diff / Debrief / Notes / Checklist / Tags, speed bars as text + bars, "wall time on this Mac; other apps affect it". Container widens to 1100px; below 700px panes stack with an A | B toggle and diff marks stay.
8. **Out of scope (v2.1):** 3+ runs, "only in A/B" item matching for checklists, star/note per run, LLM rubric scoring (recall/precision against a hand key), pasting a free reference text, speakers compare, STT×LLM grid.

## Verification
- Failing tests first: migration (cascade, unique eval key, PK per side); `POST` validations (identical 422, cross-recording 422, not-done 422, foreign group 422); `output_counts` table; warning present for different sha, absent for same sha and for no-analysis; `score_run` parity against `eval/score.py` on the real script with 3 hypotheses (perfect, one tech term dropped, all different), asserting identical numbers; eval stored once on repeated POST; no-script and no-lines cases give `eval:null`; JS tests (`node --test`; if node is missing the target prints a visible `SKIP: node not found, JS diff tests not run` line in `make test`): diff correctness on small cases (insert, delete, replace, Greek accents), op round-trip rebuilds both texts exactly, and a synthetic 1-hour pair (~10,000 words each, 5% edits) completes under 10 s in node with ≥10 progress batches and rebuilds both texts exactly.
- Orphan cleanup test: deleting one STT run of a comparison removes the comparison and it vanishes from `GET /api/comparisons?recording_id=`.
- Negative cases: two analyses on different STT runs show the warning; a pathological pair with no shared unique words still finishes (cell cap) and is flagged "coarse diff" rather than hanging.
- Manual: screenshot of a compare of two real runs (diff, counts, warning, WER table) and of the same page at phone width; with a 1-hour fixture open the tab and confirm the page stays scrollable while "Comparing…" runs (observed, not a number from here).

## Caveats
- WER here is against the script, assuming the speaker read it verbatim; ad-libbing inflates WER for every model equally, so it is for ranking, not an absolute. The TECH/NUMBERS lists in `score.py` are specific to the shipped meeting script; for other scripts those rows show `n/a` (no matching terms).
- Loading `eval/score.py` by path ties scoring to that file's location and to `jiwer`; the parity test guards drift. A later change can move its pure functions into the package and have `score.py` import them.
- The 10 s / 10,000-word budget is a test bound I chose, not a measured browser number; measure on the real 1-hour transcript in Brave.
- `analysis_group_id` depends on llm-outputs' `group_id` addition to `analysis_run`.
- Deleting a compared run removes its items by cascade and the service then deletes the leftover comparison (fewer than 2 items); nothing is left dangling.
