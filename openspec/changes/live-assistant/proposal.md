# Change: live-assistant

## Driver
Feature E, asked for on 2026-11-04: "During recording on `/record`: live transcript (Whisper turbo, like the v1 `/live` page, but inside the Record page and never endangering the crash-safe recording). Every ~2 min (configurable), Gemma E4B (cheap) only updates rolling notes, action items and tags on screen. After Stop, the normal Analyse flow still exists."

## Depends on
**run-insights (applied first)**: it creates the ONE shared `GpuLease` in `create_app` and passes it to `JobRunner`; this change only takes that lease and does not create one. The analyse step now calls `ensure_llm` and is bound with `bind(pool, *, memory=None, settings=None, hub=None)`; a test proves live takes the lease between a job's `lm_load` and `analyse` steps and the job still completes afterwards. Archived v2.0: recording-capture (WS `/api/record/ws`, `WavWriter`, `finalize`), job-runner (`GpuLease` owners `job`/`live`, `MemoryManager`), stt-runs (`stt_run`, `transcript_segment`, labels), llm-outputs (`llm/client.py`, `schemas`, `quotes.verify`, `pipeline.call_validated`). **Does not depend on llm-streaming**: a rolling update is small and shown when complete, so it uses the non-streaming `client.chat`. Independent of prompt-ab. No migration (see Decision 9).

## Decision
1. **Opt-in toggle** "Live assist" on `/record`, off by default, chosen before Mic on (the `start` WS message carries `live: true, silence_db`). Turning it on never changes how audio is captured or sent.
2. **Decoupling (recording is sacred).** In the WS handler the WAV write stays first and unchanged. After it, the handler calls `live.offer(frame_bytes, frames_before_write)`: a synchronous O(1) call that appends to a **bounded deque** (`live.max_backlog_s`, default 60 s of audio) and, when full, **drops the oldest live chunk and counts it** (drop-live-not-audio). `offer` catches every exception, never awaits and never takes a lock the writer needs; the handler also wraps it, so a bug in live can only disable live. Whisper runs in a **separate child process** (not v1's in-process thread): MLX holds the GIL during Python-side decoding and a Metal fault would kill the server and the unsynced WAV tail; a child removes both risks. A consumer task pops from the deque and never shares an executor with the writer's `to_thread`. Audio is not enqueued while waiting for the lease grant (it is dropped; the preview starts at the grant).
3. **Segmenting** = a pure class `LiveSegmenter` (numpy) ported from v1 `live_loop`: 30 ms RMS frames against `silence_db`, commit when the tail is quiet 0.5 s or the segment is over 15 s (cut at the quietest 100 ms of the last 4 s), partials every 0.8 s of new speech (`live.partials`), silence is dropped. Timestamps come from the writer's frame counter captured at offer time, so they match the saved file even when live dropped chunks. A dropped gap forces a commit before it and a restart after it, and adds to `dropped_ms`.
4. **Child worker** `details.live.worker`: persistent `mlx_whisper` with the model from `live.stt_model` (default `whisper-turbo`, must be installed per the registry, an `fast`-role model; the large model is refused in live). Line-JSON requests, raw int16 payloads, one reply line per request, exits on stdin EOF. The child prints a `ready` line after the model loads; the parent waits for it up to `live.stt_load_timeout_s` (default 120, cold load), and `live.stt_timeout_s` (default 30) applies only after ready. Parent uses separate writer and reader tasks (no request/response deadlock on pipe buffers); child stderr goes to a file in the live folder (never an unread pipe). When the worker is busy, partials are dropped and commits have priority. Parent kills the child at end, on server cleanup, and on a no-reply timeout; one automatic restart, then live STT is declared failed (recording unaffected). The `quotes`/`jiwer` imports are pre-warmed with `asyncio.to_thread` at session start, and `MemoryManager.ensure_llm`'s blocking `vm_stat` call is run through `to_thread` in live.
5. **GpuLease priority.** One `GpuLease` is created in `create_app` and given to `JobRunner` and to the live manager. A live session acquires `live` once and holds it until it ends (stop, grace-expiry finalize, WS closed without resume, app cleanup). Queued jobs stay queued meanwhile; a job step already running is never interrupted, so live shows "waiting for the running job step" and starts when granted (audio before the grant is not previewed). Only one live session at a time; a second one shows "another live session is active".
6. **Rolling notes (Gemma E4B only).** Every `live.notes_every_min` (default 2, float, 0.5 to 30) of wall time, if committed text grew since the last update and no update is in flight, call LM Studio with the previous notes + the newest live transcript (trimmed from the front to `live.max_transcript_tokens`, default 4000 estimated; E4B context is 8192) and `schemas/live-rolling.v1.json` (`notes[]`, `action_items[]` with owner or null, `tags[]`, each with `quote`). Reuses `client.chat` and `pipeline.call_validated` (one retry, never repaired). Every item's quote is then checked with `quotes.verify` against the **whole live transcript so far**; unverified items stay on screen marked "unverified" (same rule as the analysis outputs). An invalid reply after the retry keeps the previous notes and shows "update skipped". The prompt is a repo file (`rolling_prompt.md`, sha256 stored in the snapshot), not a `prompt_template`: it is not an analysis kind and prompt-ab does not list it.
7. **LM Studio unreachable / no memory.** Model load happens at the first update (`MemoryManager.ensure_llm`, off the event loop), not at toggle time, and the model is released at the end. If LM Studio is down, the load is refused for memory, or a call times out (`live.llm_timeout_s`, default 90, enforced with `asyncio.wait_for` around the call), the page shows a plain message with the URL and "Recording and live text continue"; the next tick tries again, so starting LM Studio mid-meeting recovers it.
8. **Never the 26B.** `live.llm_model` must resolve to an LLM entry with role `cheap`; anything else disables live notes with a message and issues zero loads (the role check runs in `create_app` right after `load_registry`; startup error if the id is unknown or not cheap). Live transcript only needs Whisper turbo (~1.8 GB measured) + E4B (~7 GB) + the recorder.
9. **Live preview is saved as an `stt_run`** at Stop (decided; no migration). `engine='mlx_whisper'`, `model_id=<live.stt_model>`, `status='done'`, `text` = committed lines joined, `transcript_segment` rows from the commits, `settings = {"live_preview": true, "dropped_ms": N, "silence_db": X}`, `audio_ms` = recording duration; `wall_ms`/`rtf` stay null. Label: `#n · Whisper large-v3 turbo (live preview) · done`. Why a run and not a file: (a) the Analyse flow starts from an `stt_run`, so the user can write up the meeting seconds after Stop without waiting for a full transcription; (b) the compare view then diffs live-preview against the full-pass run for free, which gives measured live accuracy; (c) no new table. Cost: it is lower quality (chunked, fast model, possible gaps), so the label says so and the run is never auto-selected for analysis. **Stop never waits on live:** the WS handler calls `live.close(deadline≈2 s)` outside `finalize`'s lock; the preview is built from commits already received, and a blocked worker (5 s) must still give `saved` in under 3 s. It is created inside `finalize` *after* the recording row exists, in its own try/except: a failure here logs and never fails the take. The rolling notes are not stored in the DB; the last snapshot and the committed lines are kept as `recordings/<id>/live/{transcript.jsonl,rolling.json}` (removed with the recording by purge). A crash/restart does not adopt the preview (files stay); only stop, grace-expiry and clean finalize do.
10. **Page**: a "Live" card (visible only when toggled) with: status line per part (speech, notes, GPU queue), transcript (committed lines solid, partial grey), three lists (Notes, Action items, Tags) with "unverified" markers and "updated mm:ss ago". `aria-live="polite"` on the status line only. On WS resume the server replays committed lines and the last notes (`live_snapshot`). The existing link to `/live` stays. The Analyse page prefers a non-live run when auto-selecting, and Library `runs_count` includes the preview run (accepted; the label says what it is).
11. **Settings** `[live]` in `config.toml`, `settings.live.*`, env `DETAILS_LIVE_<KEY>`: `stt_model`, `llm_model`, `language` ("el"), `notes_every_min`, `partials`, `max_backlog_s`, `max_transcript_tokens`, `llm_timeout_s`, `stt_timeout_s`, `stt_load_timeout_s`, `vocab_hint` (false). For the e2e test only, `create_app(live_clock=...)` (or a `DETAILS_LIVE_TEST`-gated seconds override) shortens the interval; the settings minimum stays 0.5 minutes.
12. **WS additions** (all server-to-client are additive JSON): `live_state {state: waiting_gpu|loading|listening|failed|off, message}`, `live_commit {idx,start_ms,end_ms,text}`, `live_partial {text}`, `live_notes {seq,at_ms,notes,action_items,tags,verified,unverified}`, `live_status {part: stt|notes, level: ok|warn|error, message}`, `live_snapshot`. Old clients that ignore them keep working.

## Verification
- Failing tests first (shown red): segmenter (silence dropped, commit on pause, 15 s cut, drop forces boundary, offsets match the frame counter); **decoupling** (a worker that blocks 5 s and a deque overflow: the WAV on disk is byte-identical to the input, every `writer.write` call completes with no gap above the test's bound, `offer` returns in under 5 ms per call [bound chosen by me, measure in the task], dropped count equals overflow, no exception reaches the handler even if `offer` is monkeypatched to raise); lease (`live` granted before a waiting job; running job not interrupted; released on stop, grace expiry, WS close, cleanup); rolling (fake LM Studio: verified/unverified flags, an item with an invented quote is marked unverified not removed, invalid reply keeps previous notes, interval honoured with a fake clock, no overlap, no call without new text); LM Studio unreachable mid-meeting (message, recording continues, recovery on next tick); `llm_model` pointing at a non-cheap entry causes zero `load` calls; worker death (restart once, then `live_status error`, WAV unaffected); preview run (rows, label, segments, settings flag, take shorter than 0.5 s makes none, insert failure does not fail finalize); settings validation + env override; page/JS tests.
- Negative: live off means no worker is spawned, no lease is taken, no extra WS messages; `live: true` while whisper-turbo is not installed still records and says why.
- Brave e2e (`tests/e2e/test_live_brave.py`, marker `e2e`, uses `tests/brave-playwright.json`; prints a visible `SKIP: <reason>` when Brave or Playwright is missing): the test launches the app with the fake worker + `FakeLMStudio` HTTP; an init script overrides `navigator.mediaDevices.getUserMedia` to return a `MediaStreamDestination` fed from a generated 16 kHz wav (tone bursts with pauses, built by the test, no real voice needed); steps: toggle Live assist, Mic on, see committed lines and one notes update (interval set to 2 s by env), Stop, check the Saved card and that the DB has the recording plus the live-preview run, and that the WAV/FLAC duration matches the fed audio within 50 ms. A second case: LM Studio fake down, page shows the message and the take still saves.
- `@pytest.mark.gpu` manual: real turbo + E4B for 3 minutes of the real test script read aloud; report measured RAM (`vm_stat` before/during), commit latency and one rolling update's wall time. Screenshot of the Record page in live mode, read by the implementer.

## Caveats
- **Decoupling is proven with fakes; the real MLX load (GPU, Metal) is only proven by the manual gpu task.** If the real turbo makes the machine too busy to also run Gemma, expect slow commits (the deque then drops preview audio, the recording is still whole).
- Live text is a preview: a fast model, short chunks, dropped chunks under load. Do not read the saved live-preview run as the transcript; run a full STT run for the real one.
- While Live assist is on, queued jobs wait; if a long job step is running, live starts only after it ends (a step is never interrupted), so the first minutes may have no preview.
- A resumed connection after a long drop makes the client send a burst; if it exceeds `max_backlog_s` the preview skips that part (counted in `dropped_ms`), the audio does not.
- Two features share the E4B context (8192): long meetings are fed the newest ~4000 estimated tokens plus the previous notes; very early topics survive only through the previous notes.
- The rolling prompt and schema are files, not editable in the UI, and do not go through prompt-ab.
- llm-streaming (applied second) keeps `client.chat` non-streaming-compatible; live uses the non-streaming call unchanged.
