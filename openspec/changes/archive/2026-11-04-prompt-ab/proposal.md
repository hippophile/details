## Decision
1. **Migration 0008** adds `prompt_template.checks text[] NOT NULL DEFAULT '{}'`. Why a column: the DB stores only the body, not the front matter, and the `analyse` step reads templates from the DB. A check is part of what makes a version, so it must be immutable with it. Existing v1 rows get `{}`, so v1 behaves exactly as before and the A/B stays honest.
2. **Template checks** (`llm/checks.py`): front matter key `checks: a, b` (comma list, optional). One check ships: `due_year_in_transcript` (every checklist item with a non-null `due` needs its 4-digit year as a standalone number in the text the model saw). It runs inside the same validate closure as the JSON schema, so a failure is an ordinary validation error: one retry with the error text, never repaired, then `schema_valid=false`. In map-reduce the check runs per chunk against that chunk's text. An unknown check name is a `PromptError` at parse time.
3. **`prompts/checklist/v2.md`** = v1 with the `due` rule replaced: due is non-null only when the transcript states day, month and year, copying that year; "by the 15th", weekdays, "next month" give null; never assume the current year. Front matter `checks: due_year_in_transcript`, `output_schema: checklist.v1`. v1 file is not touched.
4. **Prompts API** (`api/prompts.py`): `GET /api/prompts` (kinds, versions, latest, runs-per-version, checks); `GET /api/prompts/{kind}/{version}` (body, checks, note read from the file front matter if the file exists); `POST /api/prompts/{kind} {base_version, body, note?}` creates `prompts/<kind>/v{N+1}.md` (N = highest of DB and disk) and inserts the row. The file is created with exclusive create (temp file then `os.link`, so it can never replace an existing file); the DB row uses the file's exact bytes for `sha256`, so startup `sync_prompts` agrees. Front matter is generated by the server (name, version, kind, output_schema, suggested_params, checks copied from the base version); the user edits the body only. Save-time validation is placeholders and structure only (`{{transcript}}` present, no unknown placeholder, not identical to the base, not empty, at most 64 KB; a `base_version` that does not exist is 422). Whether the prompt still yields schema-valid output is judged at run time by the existing validate-retry path; the UI says so.
5. **Pick a version per run:** `POST /api/stt-runs/{id}/analyses` accepts `prompt_versions: {"checklist": 2}`; missing kinds use the latest. Unknown kind, unknown version, or a kind not in `kinds` gives 422. The chosen row id goes to `analysis_run.prompt_template_id`, so nothing else in the runner changes.
6. **Compare (header):** each side's pane header also shows its checks (e.g. "checklist v2 + year check"), so the reader knows v2 had a code rule v1 did not.
6b. **Compare:** no new endpoint. Analyses payload gains `prompt_version` per kind and `prompts` per group; the compare payload gains `prompt: {name, version}` per side per kind and the pane header shows "checklist v1" vs "checklist v2". Checklist `output_counts` gains `with_due` ("N with due date") so a date that disappears is visible at a glance. The group `label` is unchanged on purpose: `compare.js` matches ticks to groups by label text.
7. **Pages:** new `/prompts` (nav entry "Prompts"): kind list, version list (latest marked, runs count), read-only view, "Edit as new version" (textarea + optional note + Save), result link. The Analyse "AI write-up" form gets a version `<select>` per ticked kind, shown only when that kind has more than one version, default latest.
8. **Folded-in v2.0 issue:** invented-year due date, fixed by item 3 + 2. The first real A/B: re-run `checklist` v1 and v2 on the same transcript with the same model, tick both analyses, Compare.
9. **Note safety (blocker fix).** The optional `note` is written into line-based front matter, so it is rejected (422) if it contains CR, LF or any control character, and is capped at 200 characters. Independently, before `os.link` and the DB insert, the server runs `parse_template` on the exact temp-file bytes and requires kind, version, checks and sha256 to equal what it intended to write; any mismatch is 422 and the temp file is removed. `base_version` must satisfy `type(v) is int` (bool is refused). The kind is checked against the `KINDS` whitelist before any path is built. `{{transcript}}` presence is tested with the same `_PH` regex as `parse_template` (so `{{ transcript }}` counts).
10. **Injectable prompts dir (blocker fix).** New optional setting `[paths] prompts_dir` (a dataclass default of `<repo>/prompts`, so config files without the key stay valid; documented as a comment in `config.toml`; env `DETAILS_PATHS_PROMPTS_DIR`, absolute path) used by `sync_prompts`, `save_new_version` and `api/prompts.py`; tests point it at a tmp dir so no test touches the real `prompts/`.
11. **Default version.** A saved version becomes the default (latest) immediately for new analyses; the Analyse picker shows it preselected with its number. No setting to pin the default in this change.
12. **Out of scope:** editing `checks`, schemas or the live-assistant prompt in the UI; deleting or hiding versions; auto-picking a winner; git commit of the new file (the page tells the user to commit it); a diff view between two prompt texts (v2.2).

## Caveats
- The year check can reject a correct date when the speaker says the year in words and Whisper writes it in words ("two thousand twenty six"): the checklist would then fail after its one retry. Digits are the normal Whisper output; if it bites, v3 can relax it. This is an estimate of risk, not measured.
- The check covers the year only. A wrong day or month still passes (the quote check covers wording, not dates).
- The new file lives in the git repo folder; on the VM a version that exists only in the DB (not committed) is harmless (`sync_prompts` iterates files), but the next machine will not have it until committed.
- `prompt_template.checks` is per version and not editable in the UI in this change. A UI-saved version inherits the base version's checks.
- The year check compares the 4-digit year only as a standalone number; a year that appears only in the recording title or in an unrelated number ("2026 euros") is accepted, since the check looks at the transcript text and cannot tell a date from a quantity.
- Two machines: a version saved on machine A and one saved on B can both become `v3` with different bytes. The page warns to commit and pull before saving, and the startup error from `sync_prompts` names both sha256 values (stored and file).
- The default for new analyses stays "latest version". Saving a worse v3 changes the default; pick v2 explicitly in the form until you decide.
