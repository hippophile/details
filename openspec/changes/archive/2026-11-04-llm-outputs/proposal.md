# Change: llm-outputs

## Driver
"AI write-up: LM Studio with `response_format: json_schema`... one call per output kind, every item quotes the transcript and code checks the quote exists" (DESIGN.md §5). Cheap (Gemma E4B) and nice (Gemma 26B QAT) are both offered, neither forced (SPEC-RULES user decisions). Output language follows the transcript, with an English switch.

## Depends on
v2-foundation → recording-capture → library-page → jobs-and-models → **stt-runs** (needs `stt_run` + `transcript_segment`, the Analyse page shell).
Exact interface from `jobs-and-models` / foundation (SPEC-RULES "Integration contract"; used as written): `steps = StepRegistry()` with `@steps.register("analyse")` in `src/details/runner/steps_analyse.py` (imported in `create_app`); `JobService.enqueue(kind, recording_id, steps=[str|{name,params}], params={})`; `StepContext` (`job_id, step_name, params, cancelled, step_dir, data_dir, settings, memory, progress, spawn_child`); built-in steps `lm_load` (params `model_id`) and `lm_unload`; `@steps.on_terminal("analyse")` finalizer for cancelled/failed jobs, including queued ones. `GET /api/models?kind=llm` entries: `{id, kind, label, engine:"lmstudio", role:"cheap"|"nice"|"fast"|"accurate", needs_gb, installed, unavailable_reason?, hint?}`; models come from `models.toml` (`gemma-cheap`, `gemma-nice` shipped by jobs-and-models; this change adds none); unknown model id on POST = 422. LM Studio URL is `settings.lmstudio.url` (`DETAILS_LMSTUDIO_URL`); there is no `[llm] url`. Page served at `/analyse` from `web/analyse/index.html`; links `/analyse?rec=<id>`, `/library`. DB is the async pool; tests use `clean_db`.
This change enqueues `JobService.enqueue("analyse", recording_id, steps=[{"name":"lm_load","params":{"model_id":...}}, {"name":"analyse","params":{group_id,...}}, "lm_unload"])`.
Assumed from `stt-runs`: `stt_run.language` (`el`/`en`/`auto`), `stt_run.text`, `transcript_segment(start_ms,text)`, the `/analyse` page.

## Decision
1. **Migration 0005:** `prompt_template(id, name, version, kind, body, output_schema, sha256, created_at, unique(name,version))`; `analysis_run(id, group_id, stt_run_id → stt_run CASCADE, kind, prompt_template_id, llm_endpoint, model_id, params jsonb, output_language, input_text_sha256, rendered_prompt, status, started_at, finished_at, wall_ms, tokens_in, tokens_out, tok_per_s, finish_reason, raw_response jsonb, schema_valid, validation_errors jsonb, retry_of → analysis_run, error)`; `output(id, analysis_run_id CASCADE unique, kind, schema_version, content jsonb)`. One `group_id` per Start click = what the UI calls an "analysis". No `checklist_item` and no `tag` table: ticks patch the `output.content` jsonb and tags live in `output.content` (a tag table is v2.1).
2. **Prompts as git files:** `prompts/<kind>/v1.md` with front matter (`name, version, kind, output_schema, description, suggested_params`) and body using only `{{transcript}}`, `{{language}}`, `{{recording_title}}` (plain string replace, unknown placeholder = sync error). `sync_prompts()` runs at startup and on `make prompts`: new `(name,version)` inserted; same `(name,version)` with a different sha256 → startup error "edit = new version file". Rows never mutate.
3. **Schemas:** `schemas/<kind>.v1.json` (draft 2020-12, `additionalProperties:false`, `schema_version:1`) for `debrief` (summary; decisions, action_items{text,owner|null,due|null,done}, risks{text,severity}, open_questions — each item has `quote`), `notes` (title, sections[{heading, bullets[{text,quote}]}]), `checklist` (title, items[{text,owner|null,due|null,done,quote}]), `tags` (tags[{name,quote}], ≤8, lowercase kebab-case). `due` is `YYYY-MM-DD` or null. `summary` and titles/headings are prose, exempt from `quote`. Optional code-written `verified:boolean` per item. Diagram and speakers are v2.1.
4. **LM Studio client** `llm/client.py`: base URL `settings.lmstudio.url`; `POST /v1/chat/completions` with `response_format={"type":"json_schema","json_schema":{"name":kind,"strict":true,"schema":...}}`, `reasoning_effort:"none"`, temperature 0.1, per-kind `max_tokens`; parses `choices[0].message.content` only (never `reasoning_content`); returns `{text, tokens_in, tokens_out, finish_reason, wall_ms, raw}`. One call per kind.
5. **Validate, retry once, never repair:** jsonschema-validate; on failure make ONE retry that appends the validation error text; the retry is its own `analysis_run` row (`retry_of` → first). Still invalid → `schema_valid=false`, no `output` row, raw text kept in `raw_response`, page shows the raw text with a red note. Code never edits model JSON to make it validate.
6. **Quote check:** for every item `quote`, `norm(quote)` must be a substring of `norm(full transcript text)` (same `norm()` as `eval/score.py`). Pass → `verified:true`; fail → `verified:false`, item is kept and shown greyed with the text "unverified" (never deleted). Counts of verified/unverified are stored in the group summary.
7. **Map-reduce:** if estimated transcript tokens ≤ `settings.llm.single_pass_max_tokens` (default 20000) → one call per kind. Else split at segment boundaries into ~`settings.llm.chunk_tokens` (default 8000) chunks with a small overlap; one map call per chunk per kind; results cached on disk at `<data_dir>/cache/llm/<sha256(kind,template sha,model,params,chunk text)>.json` so a retried/resumed job skips finished chunks. Reduce: lists merged in code (dedupe on `norm(text)`), `tags` ranked by frequency (cap 8), `debrief.summary`/`notes.title` via one small reduce LLM call over the per-chunk summaries (same validate+retry rules). Token count = chars/`settings.llm.chars_per_token` estimate (default 2.5 for Greek, estimate, not measured); real `usage.prompt_tokens` is stored for later calibration.
8. **Output language:** `{{language}}` = transcript language by default (`stt_run.language`; if `auto`/null, code heuristic: >30% Greek letters → Greek else English); run option `output_language:"transcript"|"en"`. Prompts keep English terms in English.
9. **API:** `POST /api/stt-runs/{id}/analyses {model_id, kinds[], output_language}` → 202 `{group_id, job_id}` (422 if model id unknown, not `kind=llm`, kind unknown, or stt_run not `done`); `GET /api/stt-runs/{id}/analyses`; `GET /api/analyses/{group_id}` (runs, outputs, timings, tokens, verified counts); `PATCH /api/outputs/{id}/items/{idx} {done:bool}` (checklist only; one atomic `jsonb_set`, 404 bad idx, 422 non-bool, 409 other kind); `GET /api/outputs/{id}/markdown` and `GET /api/analyses/{group_id}/markdown` (`text/markdown`, `Content-Disposition` for download). Markdown is rendered from JSON by `llm/markdown.py` only (deterministic, golden-tested; `- [ ]`/`- [x]`), never parsed from model text.
10. **Page:** a "Write-up" card (source transcript dropdown defaulting to the latest done run, AI model `<select>` from `/api/models?kind=llm` showing `role` (cheap/nice) + `needs_gb`, uninstalled ones disabled with `unavailable_reason`, no forced default: Start stays disabled until one is picked; output-chip toggles Debrief/Notes/Checklist/Tags, default on; language switch Transcript/English). Result area with tabs per kind, footer `Analysis #n · model · time · tokens`, unverified items greyed + labelled, checklist as real `<input type=checkbox>` + `<label>` that PATCH on change (revert + message on failure), Copy Markdown / Download .md per tab and Copy/Download all. Analyses are listed under their transcript run in the runs list, labelled model + wall time.
11. **Terminal finalizer:** `@steps.on_terminal("analyse")` sets every non-final `analysis_run` of the job's `group_id` to `cancelled`/`failed` (with error) when the job ends that way, including while still queued.
12. **Out of scope:** diagram, speakers, transcript cleanup edits, one-click STT+AI in a single run (deferred to v2.1, see DESIGN), LLM-as-judge or the cheap-vs-nice scoring rubric, user tag editing, prompt editor UI.

## Verification
- Failing tests first, against `FakeLMStudio` in HTTP mode (`tests/fakes/lmstudio.py`, scripted replies; async pool + `clean_db`; no GPU): sync inserts then rejects an edited v1; schema files accept good and reject bad fixtures per kind; client sends `json_schema` + `reasoning_effort:"none"` and ignores `reasoning_content`; invalid → exactly 1 retry → `schema_valid=false` with no output row and raw text kept; quote verifier (verbatim pass, altered fail, Greek tonos/sigma normalisation); chunker (boundaries, overlap, cache hit skips the call, resume); reduce dedupe; language heuristic + English switch; on_terminal marks queued/running runs cancelled or failed; PATCH tick persists and survives a fresh GET, bad idx 404; Markdown golden files.
- Negative case: a fake model that invents a quote → item `verified:false`, still stored and shown "unverified"; a model that returns invalid JSON twice → no repaired output ever appears.
- Manual: with real LM Studio, run E4B on a short recording, screenshot all tabs, tick a checkbox, reload, confirm it stays; record measured wall time and tokens (label as measured on this Mac).

## Caveats
- Single-pass and chunk size are also capped by the model's `context` from `models.toml` (gemma-cheap = 8192): room = context - max_tokens - 1500, so the 20000/8000 defaults only apply to larger-context models.
- `verified` is allowed in the stored schema but stripped from the schema sent to the model and used to validate its reply.
- Observed on E4B: invented year in `due` ("1590-11-15" when only "15 Νοεμβρίου" was said); needs a prompt v2.
- Quote check is strict normalised substring; small models paraphrase quotes, so expect many "unverified" on E4B. Fuzzy matching (ratio ≥0.9, ML doc §4.4) is deliberately left to v2.1 after seeing real rates.
- `reasoning_effort:"none"` and `json_schema` were verified on Gemma E4B only; MLX 26B and Qwen are untested. Schema validity per model is itself the comparison metric.
- The 8k chunk size and the 2.5 chars/token figure are estimates, not measured; Greek may tokenise worse. Chunk size is config, not code.
- Ticks live on the one analysis they were made on; a re-run starts unticked (design rule). The page labels the latest run and does not carry ticks over.
- The combined "STT then AI in one click" flow is deferred to v2.1 (two cards for now).
- `group_id` on `analysis_run` is an addition to the data architect's sketch; compare-runs depends on it.
