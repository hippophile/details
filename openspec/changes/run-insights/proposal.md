# Change: run-insights

## Driver
User, 2026-11-04: "do them all". Features A, B, C of `design/v2/SPEC-RULES-v2.1.md`:
- **A** live pipeline view: each step of a job live with name, status, duration, model, tokens in/out, tok/s, RAM.
- **B** logs panel: per job, worker lines, model load/unload, LM Studio calls, errors; live tail plus download.
- **C** prompt inspector: for every analysis output "View prompt", "View raw reply", tokens, params.
- **Folded in (known v2.0 issue, inside this area):** on a failed or cancelled analysis the app-loaded LM Studio model stays loaded.

## Depends on

Uses as they are today: `JobRunner._run_job`, `StepContext`, `StepRegistry.on_terminal`, `JobService.run_finalizers`, `GET /api/jobs/{id}/events`, `MemoryManager.ensure_llm/release`, `analysis_run.rendered_prompt/raw_response/params`. No dependency on the other v2.1 changes. `llm-streaming` (next) builds on the call-log wrapper added here.

## Decision
1. **No migration (no 0007).** Everything A and B need is per-run, append-only and dies with the job. It already lives in `<data_dir>/jobs/<job_id>/<step>/` which `purge` deletes with the recording (SPEC-RULES: "removes `<data_dir>/jobs/<job_id>`"), so retention and cascade come for free. A DB table would add a write on every log line and a purge path. C needs no storage at all: the data is already in `analysis_run`.
2. **Step record (A).** The runner writes `<step_dir>/step.json` atomically (tmp + rename) when a step begins and when it ends: `{index, name, status: running|done|failed|cancelled, started_at, finished_at, duration_ms, error, model, tokens_in, tokens_out, tok_per_s, ram_free_start_gb, ram_free_end_gb}`. New `ctx.metrics(**kv)` merges keys (`model`, `tokens_in`, `tokens_out`, `tok_per_s`) into it. RAM = `memory.meminfo.free_gb()` (the same `vm_stat` reading the memory preflight uses) at step start and end, shown as "free RAM"; it is a system reading, not the app's own size. Steps skipped by a `done.json` marker keep their old `step.json` and show as done.
3. **Steps API and SSE (A).** `GET /api/jobs/{id}/steps` -> `{job_id, steps:[...]}` for every step in `job.steps` (not yet reached = `pending`; a `running` record on a job that is not running = `interrupted`). The existing SSE state gains one additive field `steps` (same list); existing fields are unchanged. The server re-reads a `step.json` only when its mtime changed.
4. **Job log (B).** JSON lines `{n, ts, level, step, src, msg, data}` appended to `<step_dir>/log.jsonl`; job-level lines (claimed, cancelled, finished, finalizers) go to `<data_dir>/jobs/<id>/_job/log.jsonl` (`_job` cannot collide with a step name; step names must not start with `_`). `n` is a per-job counter that continues after a restart (initialised from the highest `n` on disk). `src` is one of `runner|step|worker|llm|memory`. Per-line cap 2000 chars, per-job cap `settings.runner.log_max_lines` (default 5000) then one `log truncated` line and nothing more.
5. **What is logged.** Runner: step begin/end with duration, cancel request, failure. `lm_load`/`lm_unload`: requested model, loaded identifiers after, seconds. Worker: every child stdout line (the heartbeat lines) as `src=worker`, and on a child failure the last 20 lines of `child.stderr.log`. LM Studio calls (analyse): one line per call with `model, kind, attempt, tokens_in, tokens_out, wall_ms, finish_reason, status` (`ok | http <code> | timeout | unreachable | invalid-json`). Never prompt text, reply text or transcript text.
6. **No secrets (B, SPEC-RULES).** Every line and every `error` passes through `joblog.redact()` before it is written, and again before it is served: URL userinfo (`scheme://user:pass@` -> `scheme://***@`), `password=`/`pwd=`/`token=`/`api_key=` values, `Authorization: Bearer ...`, and the exact values of `settings.db.url` / `settings.db.url_test` / any `DETAILS_*`+`*_KEY|*_TOKEN|*_PASSWORD` env value if present. Negative test below.
7. **Log API (B).** `GET /api/jobs/{id}/log?after=<n>&limit=<=1000>` -> `{lines, next, done}` (`done` = job terminal and nothing after `next`); `?download=1` -> `text/plain` full log as readable lines with `Content-Disposition`. **Live tail by polling** that endpoint every 1 s with `after=`, not a second SSE: it is stateless, resumes after a reload for free, and the job SSE stays a small state stream. 404 for an unknown job.
8. **Prompt inspector (C).** `GET /api/analysis-runs/{run_id}/inspect` (the `run_id` the analyses API already returns per kind) -> the whole retry chain `attempts:[{attempt, run_id, retry_of, status, rendered_prompt, raw_text, tokens_in, tokens_out, tok_per_s, wall_ms, finish_reason, schema_valid, validation_errors, error}]` plus `{kind, model_id, endpoint, template:{name, version, sha256}, output_language, params}`. Honest labels: for `mode=map-reduce` `prompt_scope="first_chunk"` and `raw_text_kind="merged_by_code"` (the stored text is the code-merged JSON, not a model reply; per-chunk replies are only in the chunk cache). A retry attempt's prompt is the stored joined messages (no role labels). A call that failed before any reply has `rendered_prompt=null`.
9. **Inspector UI (C).** In each output tab an "Inspect" button opens a dialog with tabs Prompt / Raw reply / Params, a Copy button, attempt switcher when a retry exists. All text via `textContent`.
10. **Pipeline + logs UI (A, B).** In the Running card on `/analyse`: a step table (name, status icon, duration ticking live while running, model, tokens in/out, tok/s, free RAM) driven by the SSE `steps`; below it a collapsible "Log" panel with level filter, auto-scroll that pauses when the user scrolls up, and a Download link. Also reachable after the job ended (panel opens from the analysis footer using the group's `job_id`). Existing Running card elements keep their ids.
11. **Terminal unload (folded in).** The `analyse` finalizer, after setting the run rows, calls `memory.release()` (only `details-*` models; the user's own LM Studio models are never touched unless `lmstudio.exclusive`) when the job ended `failed` or `cancelled`. Guards: skipped if `settings.lmstudio.unload_on_terminal` is false (default true), skipped if another job is `running`/`cancelling`, or if the lease owner is `live` (a queued job cancelled from the API calls `run_finalizers` directly, `services/jobs.py:116`, and must not pull the model from under a running job or the live assistant), and optionally skipped when a queued job already has an `lm_load` for the same model, unload errors are logged and never change the job status.
12. **Retry semantics (why this needs a second change).** `retry` requeues "from the failed step keeping finished steps": the `lm_load` marker exists, so a retry would skip loading and call a model that the terminal unload just removed. Fix: the `analyse` step starts with `await ctx.memory.ensure_llm(entry)`, which is a no-op when the model is loaded (one `lms ps`) and loads it otherwise. A cancelled job cannot be retried (only `failed` can), so it needs nothing more. Cost: after a failure a retry pays one model load (estimate, not measured: tens of seconds for E4B, longer for 26B); benefit: no 7-26 GB parked in RAM after every failure.
13. **Shared contracts (binding, cross-change).** (a) run-insights OWNS the shared `GpuLease`: `create_app` creates one, stores it on the app (`web.AppKey`) and passes it to `JobRunner(lease=...)`; live-assistant reuses it. `app.py` is edited for this. (b) ONE step binding signature: `steps_analyse.bind(pool, *, memory=None, settings=None, hub=None)`; `bind(e.pool)` (tests/llm_helpers.py:110) keeps working. (c) The steps/log/inspect routes and the SSE `steps` field live in `api/jobs.py`/`api/insights.py`; `add_jobs_routes(app)` reads settings and data_dir from app keys, not from its arguments.
14. **Path safety and one writer.** `jobs/<id>` is built only from a UUID that came back from the DB lookup (never from the URL text). One shared `JobLog` instance per job id (a registry on the app), so runner, steps and API never race on `n`.
15. **Timing.** `started_at` and the start RAM reading are taken after the GPU lease is granted (`hold.wait()`), not at claim; a step waiting for the lease shows `status=waiting_gpu`.
16. **Secrets source.** `redact()` takes its secret values from `settings` (db urls, lmstudio url userinfo) only; no `os.environ` reads outside `settings.py`; values shorter than 6 characters are ignored (avoid masking common words). `llm/client.chat` (and later `chat_stream`) call `redact()` on any body text before putting it in `LLMError`, because that text lands in `analysis_run.error` and is served by `GET /api/analyses/{gid}`.
17. **Out of scope:** streaming of tokens (llm-streaming), log search, log shipping, per-chunk reply storage, changing `rendered_prompt` to keep roles, STT per-window metrics (STT steps show duration/RAM only; tokens columns are `-`).

## Verification
- Red first: tests listed in tasks.md fail before any code (import error / 404).
- Steps: fake step sets metrics -> `GET /steps` and the SSE `steps` field show them; resumed job shows skipped steps as done.
- Logs: lines ordered by `n` across steps and `_job`; `after=` returns only newer; restart continues `n`; cap writes one truncation line; download is plain text.
- **Negative (secrets):** a step raises `RuntimeError("could not connect to postgresql://u:SeCr3tPw@db/x")` and a fake LM Studio error body echoes `password=SeCr3tPw`; the string `SeCr3tPw` is absent from `log.jsonl`, `GET /log`, the download, `job.error` shown by the API and `step.json`. Also a bad `DATABASE_URL` value in settings is masked.
- Inspector: seeded chain with a retry returns both attempts; map-reduce seed returns the two honest labels; unknown id 404.
- Negative secrets also assert `GET /api/analyses/{gid}` `.error`. Terminal: queued-cancel while lease owner is `live` does not unload; failed analyse unloads `details-*` and leaves a preloaded user model (FakeLMStudio `calls`); cancelled-while-queued with another job running does NOT unload; retry of a failed analyse job calls `load` again and finishes.
- Page: JS unit tests (`node --test`) for row/format helpers; Brave page test for ids and `textContent`-only; screenshot of the Running card with a 3-step fake job.

## Caveats
- Free RAM is a system-wide reading, not the model's size; it moves for reasons unrelated to the job.
- A retry after failure reloads the model (cost above); that is the price of the unload.
- Map-reduce "raw reply" is code-merged JSON; the page says so. Per-chunk model replies are not stored (out of scope).
- Logs live only as long as the job directory; a purged recording takes its logs with it.
- Prompt and reply text are shown on the page (localhost only, same exposure as the transcript) but never copied into logs.
